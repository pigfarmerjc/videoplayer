# 视频画廊与播放器全面重设计规格

日期：2026-07-17  
状态：已完成会话设计评审，待书面规格确认

## 1. 目标

将 CyberPlayer 重构为专注本地视频浏览与播放的 Android 应用：主入口为高性能视频时间画廊，图片保留独立入口，完整移除独立音频库与搜索功能。播放器必须提供连续、可打断的手势体验，并把封装于视频文件中的 `PCM S24 LE` 音轨兼容性作为发布红线。

成功标准：

- 数百至数千视频时，冷缓存和热缓存浏览均保持稳定，不因缩略图任务堆积持续掉帧。
- 左右切换、下拉关闭、缩放与进度预览连续跟手，释放速度自然传递，动画可被重新抓取和反向。
- MKV、MOV 等容器中的 `pcm_s24le` 有画面、有声音、可拖动、可切换音轨，并能通过全屏、画中画与悬浮窗往返。
- 播放、媒体库、设置和平台资源各有唯一状态源与明确生命周期。
- 中文源码和资源统一使用 UTF-8，清除现有乱码。

## 2. 产品结构

应用保留三个一级入口：

1. **视频**：默认首页，纯视频时间画廊。
2. **图片**：独立图片画廊，与视频共用缩略图基础设施但不混排。
3. **资料库**：文件夹、收藏、播放历史、播放列表和设置。

完整删除：

- 独立音频扫描与音频权限。
- 独立音频播放器、导航入口和相关设置。
- 搜索入口、搜索状态和过滤逻辑。

继续保留：

- 视频文件中的音轨选择与音效控制。
- ExoPlayer 与 VLC 双内核。
- 投屏、画中画、悬浮窗、字幕、进度记忆、播放列表和媒体导出。

## 3. 视频画廊

### 3.1 信息结构

- 按“今天、昨天、本周、月份”对视频分组。
- 仅在存在未播放完视频时显示“继续观看”，最多横向展示 5 项。
- 日期标题可吸附在顶部。
- 右侧提供自动淡出的“时间胶片”快速定位控件，拖动时显示月份或日期。
- 顶部不提供搜索，仅展示当前时间范围、布局选项和必要的刷新状态。
- 长按进入多选，批量操作通过底部浮动操作栏呈现。

### 3.2 密度与缩放

- 支持 2 至 8 列密度。
- 捏合过程连续缩放，释放后吸附到最近列数；不得在手势过程中反复重建网格列数。
- 记录用户选择的布局密度与滚动位置。
- 支持原始比例与方形缩略图两种显示选项。

### 3.3 视觉系统

- 内容优先，视频封面承担主要色彩。
- 背景使用中性炭灰，避免纯黑和大面积紫青霓虹。
- 低饱和冰蓝只用于播放进度、选中状态和关键操作。
- 顶部工具栏和底部导航采用轻量半透明材料；网格本身不使用逐项玻璃卡片。
- 普通媒体项无厚阴影、复杂渐变、发光边框或持续动画。
- 密集网格使用极小圆角或无圆角；较大圆角仅用于浮层、按钮与大尺寸预览。
- 使用 Android 系统字体与统一线性图标。
- 缩略图只显示时长和底部细进度线，避免信息堆叠。

设计参考 Apple Photos 的时间层级、密度切换和捏合浏览，以及 Google Photos 通过分组和静态封面降低视觉噪音的方式；不复制其品牌视觉。

## 4. 播放器交互

### 4.1 控制层

- 默认只展示视频内容。
- 单击后显示顶部返回区、中央播放控制和底部进度区。
- 播放中数秒无操作后淡出。
- 高频控制反馈保持克制，不使用从 `scale(0)` 开始的弹出动画。

### 4.2 左右切换

- 从第一帧起 1:1 跟手，相邻视频封面同步进入。
- 使用距离与释放速度共同决定提交或取消，支持快速短划。
- 播放列表边界使用渐进式阻尼。
- 动画期间允许重新按住、反向和取消。
- 切换后立即展示目标封面，播放器准备完成后交叉淡化到真实画面。
- 按钮切换与手势切换共用同一运动模型。

### 4.3 下拉关闭

- 仅识别明确向下的拖动。
- 经过触摸阈值后锁定纵轴，避免与左右切换、亮度和进度冲突。
- 画面跟手下移，背景随距离显露，边界使用渐进阻尼。
- 释放时结合位置与向下速度决定关闭或回弹。
- 退出从当前显示位置和速度继续，不能跳变或在动画期间锁死输入。

### 4.4 其他手势

- 水平拖动调整进度。
- 左侧上下调整亮度，右侧上下调整音量。
- 双击左右区域快退或快进，中央双击播放或暂停。
- 长按临时倍速，松手立即恢复。
- 缩放和全景视频边界使用柔性阻尼。
- 所有手势由统一 `GestureSession` 管理方向锁定、位置、速度、取消与优先级。

### 4.5 减少动态效果

- 响应系统动画缩放或减少动态效果设置。
- 全屏位移、缩放和弹簧改为短淡化或静态切换。
- 保留对状态理解有帮助的颜色、透明度和进度反馈。

## 5. 拖动进度预览

- 拖动进度条时画面随目标时间变化，不只显示时间数字。
- 手势与进度指示逐帧跟手，帧解码请求合并为“只处理最新位置”。
- 过时请求立即取消或丢弃，禁止形成解码队列。
- 拖动开始时展示低延迟预览层，释放时只执行一次最终 `seekTo`。
- 优先使用播放器缓冲帧；否则使用后台生成的低分辨率帧缓存。
- 快速拖动降低采样频率，手指减速或停留时补充更清晰的准确帧。
- 时间文本、进度位置与预览画面共用同一目标时间。
- PCM/VLC 路径具备一致体验。
- 4K/8K 或低性能设备可降低预览分辨率，但不能阻塞手势线程。

## 6. 浏览性能管线

### 6.1 已确认的根因链

当前可见项冷缓存路径可能连续执行系统缩略图、黑帧检测、最多三帧回退提取、JPEG 写盘、缓存全量整理、元数据读取与偏好写入。快速滚动时，阻塞式解码和 I/O 不保证及时取消，任务会超过三路许可的吞吐量；Bitmap 完成还会触发可见项状态更新。逐项阴影、裁剪、渐变和弹簧进一步增加 GPU 与重组成本。

稳定 Lazy key 与 `contentType` 已存在，不把它们误判为主要根因。

### 6.2 新缩略图管线

- 媒体扫描只建立索引，不同步生成缩略图。
- 请求分为屏幕内、即将进入和后台预热三级优先级。
- 快速滚动时暂停新解码，只使用缓存或轻量占位；滚动减速后恢复当前视口加载。
- 同一媒体 ID 同时只允许一个请求。
- 离屏任务可取消；底层不可取消工作完成后也不得把过期结果提交给 UI。
- 帧提取、JPEG 写盘、元数据读取和缓存清理分离，磁盘工作不得占用解码许可。
- 缓存整理由独立批处理任务负责，不由单个卡片触发。
- 按实际显示尺寸解码，不保留不必要的大 Bitmap。
- GIF 或其他动态媒体在网格中仅显示静态封面。
- 网格项只在被按压时产生局部反馈。

## 7. 应用架构

### 7.1 媒体库

- `MediaLibraryViewModel` 持有唯一媒体库 UI 状态并以 `StateFlow` 发布。
- 扫描采用 single-flight、互斥与 generation；过期扫描不得覆盖新结果。
- 各媒体查询可独立失败并返回部分结果。
- 视频和图片权限分别请求；拒绝图片权限不阻止视频页面。
- 文件夹派生结果绑定媒体库 generation，不能返回过期缓存。

### 7.2 播放

- `PlaybackController` 串行管理加载、播放、暂停、切片、切换内核与释放。
- `PlayerEngine` 由 `ExoEngine` 与 `VlcEngine` 实现。
- 页面、画中画和悬浮窗共享不可变 `PlaybackSession`，不通过多个静态字段交接。
- 播放器对象不直接作为巨大 Composable 中的可变状态持有。
- 旧播放器回调不得污染新会话，每个资源恰好释放一次。

### 7.3 模块边界

- `media-library`：扫描、文件夹派生、变更操作、权限和媒体状态。
- `playback-core`：会话、控制器、双内核、进度与音效。
- `playback-ui`：播放器路由、表面、控制层、手势、轨道面板与导出协调。
- `floating-player`：服务、窗口、通知与 session ID 交接。
- `settings`：类型化 DataStore 与设置状态。
- `casting`：DLNA 发现、传输、本地媒体服务和生命周期。

`VideoPlayerScreen`、`MainScreen`、`MediaGrid` 与 `FloatingPlayerService` 按职责迁移，不做只改变文件长度的机械拆分。

## 8. PCM S24 LE 红线

### 8.1 测试素材

生成无版权短样本：

- MKV + H.264 + `pcm_s24le`。
- MOV + H.264 或 HEVC + `pcm_s24le`。
- AAC + `pcm_s24le` 多音轨。
- 立体声 48 kHz；条件允许时增加 5.1 声道。

### 8.2 播放策略

1. 默认使用 ExoPlayer 硬件视频路径。
2. 在正式播放前识别高精度 PCM 并切换 VLC。
3. 轨道无法提前识别但 ExoPlayer 报错时自动回退 VLC。
4. 验证成功后持久化该文件的内核偏好。
5. 回退保留位置、播放状态、倍速、字幕与已选音轨。
6. 全屏、画中画与悬浮窗使用同一策略。
7. 自动回退失败时显示可诊断错误，并允许手动重试另一内核。
8. 普通 AAC、Opus 等文件不得被误切到 VLC。

## 9. 错误与权限体验

- 错误使用明确状态而非未捕获协程异常或模糊 Toast。
- 区分权限未请求、可再次请求、永久拒绝和系统设置返回。
- 区分文件消失、存储卸载、格式不支持、内核失败和移动失败。
- 支持部分媒体结果与重试，不因一种权限或查询失败阻塞整个 App。
- 文件移动返回逐项类型化失败；现代 Android 使用 MediaStore/SAF 而非只依赖 `renameTo`。

## 10. 测试与验收

### 10.1 单元与集成测试

- 扫描 single-flight、取消、generation 与部分权限。
- 缩略图去重、优先级、过期结果丢弃和缓存失效。
- GestureSession 的方向锁定、距离/速度阈值、回弹和中途反向。
- 进度预览只处理最新目标，不堆积解码任务。
- Exo 到 VLC 自动回退、PCM 多音轨选择和内核偏好。
- 连续切片、旋转、画中画与悬浮窗往返后的资源释放。
- 删除音频和搜索后无音频权限、页面、路由或残留状态。

### 10.2 性能测试

- 500+ 视频的冷缓存与热缓存快速 fling Macrobenchmark。
- 比较列表、普通网格和密集画廊的帧时间、GPU 绘制与内存分配。
- 用 Perfetto 标记缩略图排队、解码、磁盘写入、元数据和缓存整理阶段。
- PCM 4K 样本拖动预览时检查主线程、解码任务积压和温度。

### 10.3 人工验收

- PCM 样本有画面、有声音、可拖动、可切音轨，并通过全屏/浮窗往返。
- 手势使用慢动作和逐帧检查，释放瞬间无速度断层。
- 中等性能真机浏览大型媒体库，无持续掉帧、异常内存增长或明显发热。
- 检查横竖屏、手势导航、刘海区域、系统栏和减少动态效果。
- 所有中文文案显示正确，无 UTF-8 乱码。

## 11. 实施顺序与范围控制

推荐顺序：

1. 建立测试样本、基线性能测量和可观测性。
2. 移除独立音频与搜索，收敛产品状态。
3. 重构媒体库 StateFlow 与缩略图管线。
4. 实现视频时间画廊与图片独立入口。
5. 建立 PlaybackController 与双内核一致会话。
6. 重写 GestureSession、左右切换、下拉关闭和进度预览。
7. 重构悬浮窗、画中画和设置交接。
8. 完成视觉系统、无障碍、性能与 PCM 验收。

不在本轮新增云同步、AI 分类、人脸识别、在线媒体搜索或音频库替代功能。
